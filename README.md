# 雲 — 인물 기록부

정적 페이지. `build.py` 가 로컬 원문(`*.txt`)을 읽어 `index.html` 을 생성한다.

## 빌드

```
python3 -m venv venv && venv/bin/pip install cryptography
venv/bin/python build.py
```

빌드에 필요한 로컬 파일 (모두 `.gitignore`, 저장소에 올리지 않는다):

| 파일 | 내용 |
|---|---|
| `content.txt` 외 `*.txt` | 본문 원문 |
| `gate.pw` | 비공개 구역 비밀번호 (또는 환경변수 `WOON_GATE_PW`) |
| `secret.txt` | 계정·인증 링크·확인 답변 등 비공개 값 |

저장소에는 생성물(`index.html`)과 빌드 스크립트만 올라간다. 빌드 스크립트에는
비밀번호도 비공개 값도 평문으로 들어 있지 않다.

## 비공개 구역

"아래는 비공개 사항입니다." 이후 구역(非說 / 연락 가능한 계정 / 성인인증 /
통합문서 확인 질문)은 **AES-GCM 으로 암호화되어** `index.html` 에 암호문으로만
실린다. 비밀번호에서 PBKDF2-HMAC-SHA256(31만 회, 랜덤 salt)으로 키를 유도하며,
평문은 저장소·배포본·개발자도구 어디에도 남지 않는다.

성공하면 유도된 키(비밀번호 원문이 아님)를 `localStorage` 에 버전 키로 저장해
재방문 시 자동 복호화한다.

### 비밀번호를 바꾸려면

`build.py` 의 `GATE_PASSWORD` 를 새 값으로 고치고 `GATE_VERSION` 을 `woon-gate-v2`
로 올린 뒤 다시 빌드한다. 버전이 바뀌면 기존 기기에 저장된 키가 무효가 되어
모든 기기에서 다시 입력하게 된다.

## 열람자 표시

`config.js` 의 Supabase URL / anon key 로 동작한다. 비워두면 표시가 조용히
사라지고 페이지는 그대로 동작한다.

## 원문 파일

`content.txt` 와 덮어쓰기용 `appearance.txt` · `nature.txt` · `chron.txt` ·
`daily.txt` · `hidden.txt` 는 `.gitignore` 라 **저장소에 사본이 없다.**
날아가면 되돌릴 곳이 없으므로 따로 백업해 둘 것.

> 2026-09-08, `nature.txt`(9203B)와 `hidden.txt`(12503B)가 통째로 NUL 바이트로
> 바뀌어 내용이 사라진 적이 있다. `build.py` 가 조용히 `content.txt` 로 되돌아가
> 빌드가 성공해 버렸고, 성정 본문이 옛 초고로 돌아간 것을 뒤늦게 알았다.
> 그때는 커밋된 `index.html` 에서 되살릴 수 있었다(비설은 게이트 암호문을
> `gate.pw` 로 풀어서). 지금은 두 파일이 있는데 비어 있으면 빌드가 실패한다.

## 캐시

`index.html` 은 `main.js?v=<해시>` / `style.css?v=<해시>` 로 참조한다. 해시는
파일 내용에서 뽑으므로 배포마다 바뀌고, 방문자 브라우저가 옛 스크립트에
머물지 않는다.

> **main.js 나 style.css 를 고쳤으면 `build.py` 를 다시 돌려야 한다.**
> 안 그러면 `index.html` 이 옛 해시를 가리킨 채 남는다.

## 접속 / 잠금해제 알림

`supabase/functions/notify` (Edge Function)가 Discord 웹훅으로 중계한다.
웹훅 URL은 함수의 secret 에만 있고 저장소·클라이언트 코드 어디에도 없다.

Discord 로 나가는 것은 **이름·종류·시각뿐**이다. 모바일에서 꺾이지 않도록
한 줄로 보낸다:

```
익명의 수달 — 기록부 열람 (9/8 09:50:23)
익명의 수달 — 封 해제, 비공개 구역 열람 (9/8 09:51:02)
익명의 수달 — 기록부 열람 종료 (14분 32초 열람) (9/8 10:05:44)
익명의 수달 — 기록부 열람 종료 (21분 · 연대·탈태 6분 · 갈맥·부작용 4분 · 성정·화이불류 3분 · 외모 2분) (9/8 10:05:44)
```

IP·위치·기기 정보는 보내지 않으며, IP 는 호출 제한에만 쓰인다 — 원본은
어디에도 남지 않고 SHA-256 앞 8바이트만 쓰인다.

### 열람 종료

보이는 동안만 시간을 잰다. 탭을 가리거나 페이지를 떠나면 그 구간을 닫고
열람 시간과 함께 종료 알림을 보내며, 돌아오면 새 구간을 연다 — 구간마다
따로 세지 합산하지 않는다. 배경에 띄워 둔 시간은 세지 않는다.

**30초 미만 구간은 보내지 않는다.** 이 문턱은 첫 구간에도 똑같이 걸린다.
모바일에서 앱을 잠깐 바꾸거나 열자마자 닫는 경우가 흔한데, 그때마다
"3초 열람" 이 오는 게 알림이 하나 빠지는 것보다 성가시기 때문이다. 그래서
아주 짧은 방문은 `열람` 만 오고 `열람 종료` 는 오지 않는다.

떠나는 순간의 일반 `fetch` 는 유실되므로 `navigator.sendBeacon` 을 쓴다.
beacon 은 헤더를 못 붙여 Content-Type 이 `text/plain` 이고 인증 헤더도 없다.
함수는 `--no-verify-jwt` 이고 Content-Type 을 믿지 않고 본문을 읽어 파싱한다.
`text/plain` 을 쓰는 것은 CORS 프리플라이트를 피하기 위해서다 — beacon 은
프리플라이트를 할 수 없다. beacon 이 없거나 거부하면 `fetch` 로 떨어진다.

`visibilitychange` 와 `pagehide` 를 모두 듣는다. 이중 발송은 구간 시작
시각을 비우는 것으로 막는다 — 앞에서 이미 보냈으면 뒤엣것은 아무것도 하지
않는다. 열람 시간은 숫자이면서 0~86400 인 것만 받고, 아니면 괄호째 생략한다.

### 체류 요약

섹션보다 한 단계 아래까지 센다 — 성정의 각 장, 갈맥의 각 항, 연대의 각 사건,
일상의 각 항목, 확인의 각 블록. 하위가 없는 섹션(외모·신원·전승·비설)은 섹션
그대로다. 현재 37곳.

판정은 인덱스 강조와 같은 기준(화면 한가운데를 지나는 것)이고, 여럿이 걸치면
가운데에 가장 가까운 것을 고른다. 탭이 보이는 동안만 센다.

열람 종료 알림에는 10초 넘게 머문 곳을 오래 본 순서로 전부 붙인다. 길어지면
뒤쪽을 `외 N곳` 으로 접는다(280자 기준). 붙일 게 없으면 시간만 나간다.
누적은 알림을 보낼 때 비운다 — 열람 시간이 '그 구간' 인 것과 눈금을 맞추기
위해서다. 잠금이 풀려 비설·확인이 새로 붙으면 다시 훑어 추적에 넣는다.

이름은 `연대·탈태` 처럼 가운뎃점을 **띄어쓰기 없이** 붙인 꼴이다. 항목을
나누는 구분자가 ` · `(양옆 공백)이라 서로 겹치지 않는다. keeper 목록에서는
읽기 좋게 `연대 · 탈태` 로 띄워 보여준다.

제목이 한자와 한글로 겹쳐 있으면 한글 쪽을 읽는다. 겹쳐 있지 않은 것만 따로
적어 두었다 — 게이트의 `非公開`, 그리고 연대의 각 사건(제목의 한글이
`師 스승` 처럼 한자를 물고 있어 그대로 못 쓴다). 일상의 물 항목은 제목이
`水, 물` 이라 앞머리의 한글 아닌 것을 떼어 `물` 만 남긴다.

好惡·習 는 일상 안에 들어 있지만 읽는 사람에게는 호오 쪽이라, 그 묶음만
호오로 돌린다.

함수는 이 값을 항목 단위로 검사한다. 전체 300자 이내여야 하고, 각 항목이
`<이름> <숫자><분|초>` 형태여야 한다. 이름의 섹션은 실제 목록에 있어야 하고
(한자 이름을 쓰던 판이 캐시에 남아 있을 수 있어 한자도 받아 한글로 옮긴다),
하위는 한글·숫자·괄호·공백 14자까지만 받는다. 하위 이름은 글이 바뀌면 함께
바뀌므로 목록으로 못 박지 않고 형태로만 거른다.

### 실시간 열람 현황 — `keeper.html`

어디에서도 링크하지 않는다. `robots.txt` 는 `keeper.html` 만 막지 않고 전체를
막는다 — 한 경로만 `Disallow` 하면 오히려 그 경로를 광고하는 꼴이라서다.

presence 채널의 각 접속자는 `{ at, name, section }` 을 싣는다 — `section` 은
`연대·탈태` 처럼 하위까지 내려간 이름이다. 섹션이 바뀌면
4초에 한 번으로 묶어 갱신한다(스크롤마다 보내지 않는다). 이 채널은 anon 키로
누구나 구독할 수 있으므로 **익명 이름과 섹션명 말고는 아무것도 싣지 않는다.**
체류 시간 같은 것은 여기 올리지 말 것.

keeper 는 구독만 하고 `track` 하지 않는다. 그래서 열람자 수에 섞이지 않고,
방문 알림도 보내지 않는다(`main.js` 를 아예 읽지 않는다).

비밀번호는 게이트와 같은 것을 쓴다. 평문은 저장소에 없고, `gate.pw` 에서
PBKDF2 로 뽑은 검증값만 페이지에 심는다. 게이트의 복호화 키와 섞이지 않도록
salt 라벨이 다르다(`woon-keeper-salt:`).

> 이 문은 속도 방지턱이지 자물쇠가 아니다. 네 자리 비밀번호는 검증값이든
> 게이트 암호문이든 오프라인에서 전수 대입이 가능하다. presence 채널도
> 마찬가지로 누구나 구독할 수 있다. 그래서 채널에 민감한 것을 싣지 않는 것이
> 실제 방어선이다.

### 익명 이름

기기마다 `익명의 <동물>` 을 한 번 뽑아 `localStorage`(`woon-visitor-name`)에
두고 계속 쓴다. 동물 풀은 58종이라 기기끼리 겹칠 수 있고, 그래도 상관없다.
서버는 이 이름을 저장하지 않고 알림 한 줄을 만드는 데만 쓴다.

이름은 방문자가 보내는 값이라 그대로 믿지 않는다. 함수는 20자 이내이면서
형태가 정확히 `익명의 <한글 1~12자>` 인 것만 받고, 아니면 `익명의 방문자` 로
바꾼다. 멘션(`@everyone`)·마크다운·줄바꿈이 웹훅으로 흘러 들어가는 것을
막기 위해서다.

### 남용 방지

제한은 같은 IP **6회/분**, 전체 **20회/분**(분산 스팸 방어) 두 겹이다.
payload 는 `type` 이 `visit`/`unlock` 인 POST 만 받는다.

카운터를 함수 메모리(`Map`)에 두면 **동작하지 않는다.** Edge Function 은
요청마다 새 isolate 로 뜰 수 있어 매번 0 으로 초기화된다. 그래서 Storage 버킷
`notify-rl` 의 "같은 이름은 두 번 못 만든다"를 원자적 카운터로 쓴다:
`<키>/<분>/<슬롯 0..N-1>` 을 차례로 만들어 보고 전부 이미 있으면 그 분의 몫을
다 쓴 것이다. 버킷은 함수가 처음 호출될 때 스스로 만들고, 지난 분의 객체는
그 다음 분 첫 호출 때 지운다. 저장되는 값은 IP 해시 8바이트가 전부다.

> Storage 는 중복일 때 HTTP 409 가 아니라 **HTTP 400** 을 주고 본문에만
> `{"statusCode":"409","code":"KeyAlreadyExists"}` 를 담는다. 상태코드만 보면
> 중복을 놓쳐 제한이 통째로 무력화되니 본문을 봐야 한다.

### 내 기기에서 알림 끄기

브라우저 콘솔에서 한 줄:

```js
localStorage.setItem('woon-owner','1')   // 끄기
localStorage.removeItem('woon-owner')    // 다시 켜기
```

방문 알림은 세션당 1회(`sessionStorage`), 잠금해제 알림은 비밀번호를 직접
입력해 성공했을 때만 보낸다(저장된 키로 자동 해제될 때는 보내지 않는다).
전송 실패는 조용히 무시되어 페이지 동작에 영향이 없다.
